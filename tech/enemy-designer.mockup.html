What the chat costs, mechanically. This is the part that differs from the earlier plan — worth agreeing on before it becomes a spec.

One turn, end to end

  1. Compose messages: system (buildSystemPrompt(), unchanged) + current sparse spec + last N turns + your message.
  2. client.chatJSON → a reply with two parts: prose, and a spec (or none).
  3. No spec → it was a question. Append the prose. Done.
  4. A spec → accept(): validate → normalize → dry-run. Unchanged, already shared with Save.
  5. Fail → one repair round with the errors verbatim. Still failing → transcript keeps the failure, spec untouched.
  6. Pass → swap the spec, push a checkpoint, diff old vs new for the tree marks, re-instantiate the preview.

What has to be new

PieceWhereSize
chatEnemySpec()generate.js — replaces both generate and revise~70 lines
Two-part replyAsk for { "reply": "…", "spec": {…}|null }. The JSON-object discipline the prompt already enforces still holdsprompt only
Transcript + checkpointsTool state: array of turns, array of specs~60 lines
Spec diffNew pure module — walks two sparse specs, returns touched paths~90 lines, node-testable
Manual edits → transcriptSynthetic system turn per edit, debounced and merged by path. Own slice, and optional — the current spec is attached every turn, so the model already sees your edit; this only makes the transcript read honestly~35 lines

accept(), validateSpec, normalizeSpec, dryRunSpec and buildSystemPrompt() are all reused as-is.

Decisions this forces

QuestionMockup assumes
Does every reply carry a whole spec?Yes, whole. Patches would need a second validated format (EnemyPatch in tech/enemyspec-llm.md §2.2). Whole specs cost tokens and buy one acceptance path
How much history goes back?Last 6 turns, prose only. Superseded specs are dead weight — the current one is always attached
Undo model?Rewind to a checkpoint. No accept/discard per turn — that was the old plan and a chat makes it redundant
Manual edit mid-conversation?Allowed. The attached spec carries it regardless; narrating it in the transcript is a later slice, for readability rather than correctness
Preview during a turn?Keeps running on the old spec, swaps on landing

Where this gets expensive

Token growth is the real cost. A boss-shaped sparse spec runs 3–5KB. Attaching it every turn plus six turns of prose is ~4k tokens a message, and it only goes up. The cap is the reason history is prose-only and specs are never repeated in the transcript.
The model rewrites what you did not ask about. Unavoidable when every reply is a whole spec. The diff and the touched-node marks are the mitigation — you see it, in the rail, without reading JSON.
Streaming is not free. chatJSON waits for a complete object today. Token-by-token prose would need a second streaming path in src/player2/client.js. The mockup's working-state is honest about that: dots and a skeleton, not a live typewriter, unless you want that path built.
